# Pose cache method review — 2026-10-07

The full rebuild compares local model candidates on identical clips before admitting any training data. The selected operational extractor is **YOLO11m@640** because it preserves the existing COCO-17 contract, retains high coverage on slow, 60 FPS, and multi-coach clips, and is materially faster than YOLO11x@960. The local YOLO26m/x models were rejected for catastrophic coverage on Funkytown in the fixed probe.

**Foundational direction.** The durable fix is a detector/pose/tracker pipeline: explicit source timestamps, per-person top-down estimates, persistent coach identity, finite-to-finite jump gating, bounded missing-frame masks, and no averaging of people. Audio is decoded separately and bound by its fresh waveform hash. Missing observations remain masked; interpolation is limited to the existing timestamp rule.

**Other models.** RTMPose-m is a strong top-down candidate and had near-complete coverage in the local probe, but this environment exposes only a CPU ONNXRuntime backend (about 2.4–2.9 FPS), so it is not practical for this full rebuild. RTMO is a promising one-stage multi-person alternative; RTMW adds whole-body keypoints but requires a skeleton mapping and is unnecessary for the current COCO-17 contract. ViTPose++ is a high-accuracy top-down alternative but requires a separate detector and would need a GPU deployment benchmark. Sapiens2 provides 308 whole-body keypoints and a DETR detector, but its keypoint convention requires an explicit mapping and its released pipeline is too large to substitute without a new contract.
