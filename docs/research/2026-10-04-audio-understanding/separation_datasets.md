# Source-aware audio datasets for LightSem

Research date: 2026-10-04. Primary project pages, author repositories and dataset releases inspected; no audio downloaded and no training performed. Recommendations below are proposals, not experimental results. Dataset/audio permissions are distinct from repository-code or model-weight permissions.

## Important controls before using these data

1. **Slakh duplicate leakage:** original splits contain repeated MIDI rendered with different instruments across train/test. Use the named `redux` release or `split2`, never silently use original splits. `split2` preserves all 2,100 tracks but groups MIDI duplicates within splits. For onset/note labels use each source's `SXX.mid`, which is the file actually rendered; `all_src.mid` can differ because of synthesis heuristics. [Author documentation](https://github.com/ethman/slakh-utils).
2. **Cross-dataset leakage:** MUSDB18 incorporates 46 MedleyDB recordings. Treat them as the same song across both corpora; splitting clips or stems independently is invalid. MUSDB18 and HQ are alternate encodings of the same tracks, not independent datasets. The SigSep page lists several bleeding/mislabeling cases and one left-channel mixture-sum issue, so inspect residuals before treating every stem as clean truth. [Official provenance and errata](https://sigsep.github.io/datasets/musdb.html).
3. **Generalization:** split all stems, edits and crops of a song together; use artist-grouped validation where possible. No canonical MoisesDB train/validation/test split was established in the official material inspected. Freeze and publish a manifest before LightSem training. Maintain a separate real-song test set when pretraining on synthetic Slakh. This is our proposed protocol.
4. **Stereo is not room geometry:** stereo mastering can place a source across both channels and include reflections/effects. Infer balance, width, phase coherence and movement in the stereo image, with confidence. Do not claim these datasets teach physical 3D musician positions. This is a methodological inference from the released formats.
5. **Do not overclaim annotation quality:** waveform-derived onsets, inferred beats and pretrained-separator stems are pseudo-labels unless independently checked. Silence/activity labels, melody pitch curves, drum identity labels and human note-onset annotations are different supervisory targets. Keep their provenance and confidence separate.

## Proposed LightSem use

Start with **Slakh-redux for controlled source/event representation learning**, then validate source activity, identity and event timing on **MoisesDB/MedleyDB real multitracks**. Reserve MUSDB18-HQ for a standard coarse-separation check and stereo regression tests. Avoid collapsing all instrumentation into MUSDB's “other” when the intended representation must distinguish piano, guitar, pads, percussion and lead instruments.

Suggested representation targets are per-source identity/activity, onset/offset density, loudness envelope, pitch/register where defined, drum-event type where supported, beat-relative event positions and stereo-image descriptors. Source removal, temporal displacement and panning interventions can supply controlled counterfactual tests. Derive the intervention directly from an isolated source and retain its original timing for the unchanged sources. These are proposed uses of the available audio/MIDI, not labels universally supplied by the datasets.

Keep source reconstruction as an auxiliary objective or teacher check; LightSem ultimately needs reliable event and relationship information, not merely high waveform separation scores. Test absence detection, onset localization and source-specific response before integrating with dance/light mapping. Freeze P2 color settings and the accepted body-to-light mapping for downstream comparisons; neither dataset training nor a separator result by itself qualifies new choreography or a new demo.

For acquisition, save the exact dataset version, upstream URL, archive hash, split manifest, per-track origin and accompanying license text.
