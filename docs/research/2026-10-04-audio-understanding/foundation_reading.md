# Audio foundation representations: checked family map

Research date: 2026-10-04. Literature and implementation inspection only; no training, checkpoint downloads, model promotion, or vault mutation.

Earlier LightSem negatives constrain the exact tested recipes. They do **not** exclude generic pretrained encoders, new objectives, learned layer mixtures, adaptation, or multi-task representation training. The proposed sound-understanding stage merits a direct test of musical information before judging its downstream usefulness from choreography alone.

## Seven candidate entries

| Family | What the representation exposes | Public artifact versus paper | Fair new LightSem experiment |
|---|---|---|---|
| **MERT-v1** | Masked prediction using acoustic RVQ and musical CQT teachers. Released 330M model provides 24 layers of 1024-D temporal features at 75 Hz from 24 kHz mono; pooling is optional. | Actual 330M and 95M weights exist. Local 330M checkpoint already available. Weight card: CC-BY-NC 4.0; source: Apache 2.0. [Paper](https://arxiv.org/abs/2306.00107), [card](https://huggingface.co/m-a-p/MERT-v1-330M), [code license](https://github.com/yizhilll/MERT/blob/main/LICENSE). | Reuse dense features as a strong economical baseline; choose layers against source/activity/rhythm labels, not motion-only regression. Test a learned multi-layer readout or adapters separately from the old fixed-layer/PCA/concatenation recipe. |
| **MERT-v2-30s / FullSong** | New 632M, 24-layer, 1024-D, 25 Hz encoder. Multi-view quantized targets jointly reconstruct frozen MuQ and Qwen2-Audio features. FullSong extends bidirectional context to 30–360 s. | Public checkpoints, announced with YuE2 on 27 September 2026; full-song card specifies CC-BY-NC 4.0 weights. Encoder is distinct from the paper's separately adapted causal semantic tokenizer. Comparative baselines were imported from other reports, not all rerun. [Paper §3.1/B.1](https://arxiv.org/html/2609.33757v1#S3.SS1), [FullSong card](https://huggingface.co/m-a-p/MERT-v2-FullSong), [30s card](https://huggingface.co/m-a-p/MERT-v2-30s). | A new checkpoint/objective/context family, not repetition of MERT-v1. Test fixed 30 s and longer-context variants on phrase/instrument activity with matched crops; benchmark memory before full-song extraction on 12 GB. The two-teacher bottleneck is also an implementable distillation recipe for a smaller student. |
| **MuQ / MuQ-MuLan** | MuQ predicts Mel-RVQ codes and exposes 25 Hz dense features from 24 kHz audio. MuQ-MuLan adds text-aligned pooled music semantics. These are different interfaces. | Public MuQ uses MSD; authors explicitly warn it differs from the larger 160k-hour in-house model in paper results. Code MIT; both released weight families CC-BY-NC 4.0. [Paper methods](https://arxiv.org/html/2501.01108v2), [official release and licenses](https://github.com/tencent-ailab/MuQ#model-checkpoints). | Keep locally cached MuQ in the comparison. Instrument/event supervision and multi-scale readouts ask a new question despite old motion-probe failures. Compare dense MuQ against pooled MuQ-MuLan on semantic tasks; do not treat either as validated timing supervision without annotation tests. |
| **MusicFM** | BEST-RQ-style random-quantized masked prediction with a Conformer. Public interface provides native 25 Hz frame features from 24 kHz input and selectable layers; global pooling is an optional downstream choice. Paper explicitly evaluates beat, chord and section tasks alongside tagging/key. | Public FMA and MSD weights; README says MSD release is **not** the model introduced in the paper. Checkpoint card MIT; source mostly MIT, FlashConformer Apache 2.0. [Paper](https://arxiv.org/html/2311.03318v1), [implementation](https://github.com/minzwon/musicfm), [weight card](https://huggingface.co/minzwon/MusicFM), [source licenses](https://github.com/minzwon/musicfm/blob/master/LICENSE). | A proper general-purpose temporal baseline. Match native timestamp alignment, dense output, context, normalization, and task readout. Its paper supports testing these design choices; it does not establish LightSem transfer. |
| **BEATs** | Iteratively learns an acoustic tokenizer and masked-token audio encoder. Official 90M model uses 768-D states;16 kHz / 128-bin filterbanks and 16×16 patches imply 160 ms temporal patches. Flattened token count includes frequency positions. Fine-tuned classifier output is pooled. | Multiple pretraining iterations, tokenizers, and AudioSet-fine-tuned checkpoints publicly linked. Repo points to root MIT license; downloaded checkpoint-specific notices remain to inspect. [Paper methods](https://arxiv.org/html/2212.09058v1), [official models/API](https://github.com/microsoft/unilm/blob/master/beats/README.md), [license](https://github.com/microsoft/unilm/blob/master/LICENSE). | Test generic sound/instrument semantics and local activity with the **pretrained feature API**, not just its classification probabilities. Retain time/frequency layout. BEATs is not a beat tracker; drum subdivision accuracy must be measured. |
| **CLAP / MuLan-style audio–text encoders** | Text-aligned semantics are useful for instrument/event names and descriptions. Standard CLAP audio embeddings summarize a crop. Official HTS-AT implementation also exposes `fine_grained_embedding`; internal temporal features therefore exist, although contrastive clip-level training does not certify event alignment. | LAION provides general, music, and music+speech releases. Exact HF `laion/larger_clap_music_and_speech` card lists Apache 2.0; original LAION repo code lists CC0. Do not transfer either label to every CLAP implementation. Compare dense internal states, sliding-crop semantics, and pooled embedding with exact context disclosure. Pair it with onset/source labels rather than assuming text agreement supplies rhythm. |
| **Audio-JEPA (generic masked latent prediction)** | Predicts latent spectrogram patches instead of samples. Released ViT-base encoder gives 128×768 tokens per 10 s, but grid has only 16 temporal positions: roughly 625 ms/position, 1.6 Hz. Frequency patches are not additional time resolution. | Official author repo and HF encoder checkpoint now available, with MIT source/card. Distinct from A-JEPA (2023), Stem-JEPA, and the author's later BEST-RQ-2. [Paper abstract](https://arxiv.org/abs/2507.02915), [author repo](https://github.com/LudovicTuncay/Audio-JEPA), [explicit interface](https://huggingface.co/ltuncay/Audio-JEPA). | Fair generic latent-learning comparator or semantic-context branch. For fine rhythm, independently test dense readout limitations or change patching in a separately trained arm. Coarse time grid is a concrete architectural fact, not grounds to reject the learning objective. |

## What a useful re-test changes

These are proposals, not measured results:

1. Preserve native temporal tokens and explicit timestamps. Evaluate pooling as an ablation, not a preprocessing default. Resampling 25 Hz to 40 Hz does not create new temporal observations.
2. Probe source identity/activity, instrument, onset/offset, beat/downbeat, subdivision and phrase boundaries separately. Tune layer choice and readout only within development training folds, including same-BPM cross-song comparisons and source interventions.
3. Compare frozen dense features, learned layer mixture, parameter-efficient adaptation, and distillation into a small student as different arms. A generic encoder may have useful information that the historical decoder failed to use; conversely, a capable probe can expose a useful feature without proving lighting improvement.
4. Keep an explicit low-latency onset branch or fine-frame targets where needed; long-context semantics and rapid transients need not share one temporal resolution. Test whether heads cooperate rather than assuming source decomposition is always necessary.
5. Retain stereo before every mono teacher. Mono teachers can supervise semantic branches; they cannot supply missing left/right phase cues. Music mixing position and physically calibrated3D direction require different labels.
6. Measure per-head variance/rank and source interventions. A high-rank latent or strong tagging result alone neither proves source disentanglement nor establishes input-sensitive movement. Downstream P2/body/DMX tests remain a later, separate gate.

The primary baseline suite should be broad enough to answer whether decomposition helps: current Audio94; dense MERT-v1/MuQ; at least one untried temporal family such as MusicFM or MERT2; a generic semantic model such as BEATs/CLAP; then structured source-aware objectives. Do not predeclare the structured model the winner.

## Adjacent mechanisms checked

**SD-Codec** explicitly assigns source domains to quantizers and jointly reconstructs separated signals and mixtures. It is a useful mechanism for meaningful latent partitions, but its demonstrated domains are **speech/music/sound effects**, not bass/drums/instruments. It uses 16 kHz audio and roughly 6,000 h training; author code reports 8×A100-80GB and links pretrained weights. Repo code MIT; separate weight terms were not established in this audit. A music-specific adaptation would require new source labels and should be reported as such. [Paper method and experiments](https://arxiv.org/html/2409.11228v2), [official repository](https://github.com/XiaoyuBIE1994/SDCodec).

**Mixture2Music** was checked to avoid a name-level mismatch. The located work assigns instruments to notes in an unlabeled **symbolic piano roll** and constrains the assigned notes to the original mixture. It is not a waveform stem separator or ready audio teacher. Mixture-consistent latent reconstruction remains an interesting transferable principle; the task itself would need transcription or synthetic MIDI supervision. [Primary workshop paper](https://neuripscreativityworkshop.github.io/2022/papers/ml4cd2022_paper01.pdf), [arXiv metadata](https://arxiv.org/abs/2209.02696).

**SONAR** is ambiguous: Meta's sentence-level speech/text embeddings and a spectral deepfake detector are different projects, neither automatically a music teacher. Search also surfaced a title about self-distilled continual audio pretraining, but a verified primary artifact was not obtained; no recommendation is based on that title. [Meta SONAR paper](https://arxiv.org/abs/2308.11466), [different deepfake paper](https://proceedings.mlr.press/v306/hidekel26a.html).
